# Changelog

All notable changes to the Phantom Portals canon. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [ADR-0010](decisions/ADR-0010-canon-governance.md) (semantic versioning for the canon).

Dates before 1.0.0 are reconstructed from the version stamps of the owner's Claude artifacts.

## [1.1.0] — 2026-10-30

Owner direction of 2026-10-29 filed; the design system reaches shadcn/ui (for Codex), Figma and Canva.

### Added
- **Owner directions** (`00_START_HERE/directions/`): the 2026-10-29 white-forward Trash Polka standard, verbatim, with a measured comparison of its palette against the tokens.
- **Status vocabulary** (`10_DESIGN_SYSTEM/components/status-vocabulary.*`): the Universal Canon's 10 truthful states and 5 evidence labels, mapped to StatusBadge shapes; live in the gallery ([ADR-0012](decisions/ADR-0012-status-vocabulary.md)).
- **Adapters** (`10_DESIGN_SYSTEM/adapters/`, [ADR-0013](decisions/ADR-0013-tool-adapters.md)) generated by `80_TOOLS/build-adapters.py`: shadcn/ui `registry:theme` + Tailwind v4 `globals.css` (light = white-forward, dark = inverse regions), Figma variable spec (3 collections, 86 variables, 16 text and 6 effect styles), Canva Brand Kit sheet, a 9-page brand board, and a 42-pairing contrast report.
- **Canva kit** ([adapters/canva/README.md](../10_DESIGN_SYSTEM/adapters/canva/README.md)): folder *Phantom Portals — Design System*, 14 brand and Ink Protocol assets uploaded as transparent PNGs, and a 9-page design-system board built from `brand-board.html` (`80_TOOLS/generators/render-brand-board.cjs`).
- **Test** `80_TOOLS/tests/shadcn-theme`: compiles the theme with Tailwind 4.3.3 and checks the rendered colours, radii and fonts in Chromium.
- **Validator check** `adapters` (eleven checks).
- **Universal Canon v4** (USB engineering laws), verbatim, with a status note; **Codex hand-off v1.1** (five-gate work order, AGENTS.md snippet, ledger entry).
- **Pointers** (not files) for the DGAS Trash Polka Photoshop action and the shadcn/ui source.
- `tokens.json`: the v3.1 prototype values recorded as `$extensions.com.phantomportals.v31` mappings (no value changed).

### Changed
- `.gitattributes`: files are stored byte-for-byte (`* -text`). The 1.0.0 rules normalised line endings, so a git clone changed 10 CRLF/LF files and broke the archive seal and release manifest; found by cloning and validating before the first push.
- `feedback.md`: `idle` badges are `ink-primary` (the shipped CSS), not `ink-secondary`.
- `retired-canon-negative.md` 1.1.0: adds the Cyberpunk direction.

### Retired
- 2026-10-17 Cyberpunk direction (Universal Canon v4 Law 4) — register CR-096.

### Open
- Figma library not built (connector not enabled); USB adoption pending Codex.

### Decided
- **C-08** palette: the owner kept the canon tokens ([ADR-0011](decisions/ADR-0011-palette-reconciliation-v31.md) accepted). The v3.1 values remain as mappings; `#CE102B` maps to `accent-crimson`.

## [1.0.0] — 2026-10-29

First assembled canon. Everything below *Pre-canon history* was consolidated into this folder.

### Added
- **00_START_HERE**: README, canon register (CURRENT / RETIRED / UNCLEAR / REFERENCE / DRAFT), this changelog, decision records ADR-0001 … ADR-0010.
- **Design tokens in W3C DTCG** (`10_DESIGN_SYSTEM/tokens/tokens.json`), converted from design-system tokens v2 with every value preserved; built with Style Dictionary 5.6.1 into `tokens.css`, `typography.css`, `fonts.css`, `index.css`, `tokens.ts`, `tailwind.tokens.js`, `tailwind.theme.css`, `tokens.resolved.json`, `tokens.global.js`. All 74 CSS variables match the design system's original `tokens.css`.
- **Design-system docs**: foundations (colour, typography, spacing & grid, breakpoints, elevation & borders), visual language (Trash Polka rules, isometric HUD rules, composition ratios, do/don't, the Phantom, Ink Protocol), components (ten families plus a backlog), motion & VFX, iconography, accessibility (WCAG 2.2 AA checklist, focus states, computed contrast matrix).
- **Offline gallery** rendering the real component library with local fonts, icons and art; verified from `file://` with no network at 1440 and 390 px.
- **`icons.data.js`**: the 20 UI icons as `data:` URIs, so pages opened from disk can show the library's mask-based icons (browsers block CSS mask images on `file://`, and relative `url()`s in custom properties resolve against `bundle.css`).
- **Prompt library**: 27 prompts with a front-matter schema — 13 image-generation (hero, backgrounds, textures, HUD overlays, thumbnails, album art), 5 coding-agent build, 4 design-audit, 4 shared negative lists, plus the template; generated `INDEX.json`.
- **Asset library**: 7 logos/wordmarks, 5 artwork PNGs including Plate 01, 19 vectors, 20 UI icons, 20 feature icons, 8 font faces with OFL licences, 4 layered SVG media templates (YouTube thumbnail, lower third, album cover, channel banner) drawn by a deterministic generator — each with a provenance sidecar (origin, asset id, SHA-256, licence, usage rules); generated `INDEX.json`.
- **Mockups** from the Claude Design canvas (six screens), clearly separated third-party references with source URLs, and the first dated screenshot.
- **Agents**: project instructions for any AI tool; the owner's Trashy Mr. Polka BOT brief (verbatim); the Codex v3.1 handoff.
- **Templates**: HTML/CSS starter (offline shell with the interim phone CSS), six-layout HTML deck with PDF printing, document template, thumbnail notes (PSD/AFDesign not included — made from the SVG template).
- **Tooling** (offline, stdlib Python + pinned Node): `build-tokens.sh/.ps1`, `contrast-matrix.py`, `index-assets.py`, `index-prompts.py`, `build-icon-data.py`, `hash-manifest.py`, `generators/make-media-templates.py`, `validate-canon.py` (ten checks, each tested against an injected fault).
- **Archive**: XerXes style lock, Ruby Edition (asset-pack docs and design system), Operator System, v1 flat vectors — with asset-pointer lists for binaries left in their source artifacts; sealed by `ARCHIVE_MANIFEST.sha256` (89 files).
- **Release** `99_RELEASES/v1.0.0` with `MANIFEST.sha256` and release notes.

### Changed
- `radius-0` is emitted as `0px` instead of `0` (identical rendering).
- Shadows are stored as DTCG shadow objects and emitted with explicit `0px` spreads (identical rendering).

See [Open conflicts](CANON_REGISTER.md#open-conflicts) C-01 … C-07 and the [component backlog](../10_DESIGN_SYSTEM/components/BACKLOG.md).
